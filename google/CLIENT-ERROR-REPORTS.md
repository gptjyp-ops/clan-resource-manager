# 자동 오류 접수 및 운영자 대응

클랜원은 문제를 해결하거나 오류를 복사해 보낼 필요가 없습니다. 입장, 저장, 클랜장 관리 화면에서 오류가 표시되면 프런트엔드가 **오류 코드와 안전한 기기 정보**를 자동 전송합니다. 화면 밖에서 발생하는 처리되지 않은 JavaScript 오류도 `CRM-GEN-002`로 자동 전송합니다.

## 전송 구조

1. 클라이언트가 `CRM-...` 코드, 발생 시각(UTC), 고정된 화면 이름, OS, 브라우저, 웹앱 빌드 SHA, 임의 보고 ID를 생성합니다.
2. 사용자 입장 절차나 Apps Script iframe 연결을 통하지 않고 `/exec`의 `doPost`에 직접 전송합니다.
3. 서버는 값의 형식과 건수(전체 300건/일)를 확인하고 비공개 스프레드시트의 `client_errors` 탭에 기록합니다.
4. Google Apps Script 실행 계정 메일로 신규 코드별 최대 15분에 한 통, 하루 최대 20통을 발송합니다(메일 수신자가 확인되는 경우에만).
5. 네트워크가 끊기면 브라우저에 최대 20건을 보관하고 다시 접속하거나 온라인 상태가 되면 재시도합니다. 동일 코드와 화면은 10분 안에 재등록하지 않습니다.
6. 클랜 재화 오류 검토 자동화가 `ocr_errors`와 `client_errors`를 함께 읽도록 설정되어 있습니다.

비밀번호, 초대 코드, QR 인증 토큰, 닉네임, 사용자 원본 사진, 주소 URL 및 자바스크립트 원문 예외 메시지는 자동 전송하지 않습니다.

> **중요:** 브라우저의 `no-cors` 직접 전송은 서버 응답을 확인할 수 없으므로, 클랜원 화면에는 '전송 시도'로만 표시됩니다. 보고가 확실히 접수되었다고 표시하지 않습니다. 서버 장애 시 전송이 지연될 수 있습니다.

## 오류 코드 표

| 코드 | 의미 | 운영자 조치 |
|---|---|---|
| CRM-CON-001 | iframe 구글 연결 시작 30초 초과 | 앱 내부 브라우저/추적 차단 설정, 웹 앱 배포 권한, URL 점검 |
| CRM-CON-002 | Google RPC 응답 지연 | 중복 저장 주의, Apps Script 실행 로그·시트 반영 확인 |
| CRM-CON-003 | 구글 웹 앱 주소·설정 이상 | 환경 변수, Google /exec 배포 확인 |
| CRM-CON-004 | 일반 통신 실패 | 네트워크, 브라우저, 구글 서버 상태 확인 |
| CRM-VER-001 | 구글 스크립트 버전 불일치 | Google Code.gs 최신판 배포 |
| CRM-AUTH-001 | 클랜 입장 코드·비밀번호 불일치 | 사용자에게 입력 정보 확인 안내 |
| CRM-AUTH-002 | 수정 비밀번호 불일치 | 회원 비밀번호 재설정 경로 안내 |
| CRM-AUTH-003 | 로그인 시도 임시 제한 | 10분 제한 확인, 시도 반복 중단 |
| CRM-INV-001 | 초대 링크 만료·불일치 | 새 링크 발급 |
| CRM-QR-001 | QR 티켓 만료·불일치 | 개인 QR 재발급 또는 클랜장 복구 |
| CRM-PHOTO-001 | 사진 형식·크기 오류 | 저장용 사진 변환·용량 확인 |
| CRM-SAVE-002 | 회원 데이터 동시 변경 | 최신 상태 재조회 후 필요한 항목만 저장 |
| CRM-SAVE-003 | 동일 시점 요청 충돌 | 응답 확인 후 재시도 |
| CRM-ADM-001 | 클랜장 인증 만료·불일치 | 관리자 재로그인 |
| CRM-REC-001 | 계정 복구 정보 불일치 | 복구 코드·이메일 확인 |
| CRM-GEN-001 | 아직 분류되지 않은 오류 | 원인 분석 후 고정 코드 추가 |
| CRM-GEN-002 | 처리되지 않은 웹앱 예외 | 빌드 버전·브라우저별 재현 후 원인 확인 |

## 적용 절차

1. GitHub의 `src/ConnectionHelp.tsx`, `src/lib/client-error-report.ts`, `src/main.tsx`와 `.github/workflows/pages.yml`은 main에 반영되어 있습니다.
2. **구글 Apps Script 편집기에서** 최신 `google/Code.gs` 파일 전체를 반영하고, 기존 배포를 **배포 관리 → 수정 → 새 버전**으로 게시해야 서버 수신 기능이 실제 활성화됩니다. 클랜원이나 클랜 비밀번호에 손대지 않습니다.
3. 메일이 자동으로 오지 않으면 Script Properties의 `ERROR_ALERT_EMAIL`에 **운영자 본인 이메일**을 설정합니다. 값이 없다면 `Session.getEffectiveUser().getEmail()`로 확인되는 구글 스크립트 실행 계정에게 보냅니다.
4. 오류를 1회 재현한 후 Google Sheet의 `client_errors` 탭에 새 기록이 남는지와 운영자 메일 수신을 확인합니다. **두 결과를 확인하기 전에는 접수 시스템 운영 완료라고 보고하지 않습니다.**
