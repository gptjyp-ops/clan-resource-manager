# 복구 이메일과 메일 비밀번호 재설정

신규 회원은 재화 최초 등록 시 복구 이메일을 입력합니다. 등록 직후 보낸 인증 메일에서 버튼을 눌러야 복구 주소가 활성화됩니다. 기존 회원은 내 재화의 **이메일로 비밀번호 찾기 · 복구 이메일 등록**에서 현재 비밀번호 또는 본인 QR로 인증 후 이메일을 등록·변경합니다. 미인증 새 주소는 기존 인증 주소를 덮어쓰지 않습니다.

로그인 화면에서 닉네임과 인증한 이메일을 입력하면 비밀번호 재설정 링크를 받습니다. 15분 만료·일회용이며, 링크를 여는 것만으로 변경되지 않습니다. 새 비밀번호와 확인을 제출해야 변경됩니다. 이메일로 현재 비밀번호를 보내지 않습니다. 재화·사진은 유지하고 이전 비밀번호·QR·비밀번호 백업·기존 복구 코드는 무효화합니다.

복구 이메일 상태는 해당 회원 시트의 I열 `recovery_email_json`에만 보관합니다. 공개 현황·회원 API에 포함하지 않으며 URL/콘솔에 이메일이나 비밀번호를 출력하지 않습니다. 메일에는 사용자가 요청한 비밀 링크만 포함합니다. 토큰 원문은 저장하지 않고 HMAC만 저장하며 클랜·닉네임·현재 인증 salt에 묶습니다. 회원 삭제와 재등록 시 이전 링크와 주소는 상속되지 않습니다. 회원당 1분 간격, 시간당 5회, 전체 하루 80회 제한을 둡니다.

## 메일 권한 활성화 — 배포 전 소유 계정에서 한 번

Google MailApp는 `https://www.googleapis.com/auth/script.send_mail` 권한이 필요합니다. Google 웹 앱은 소유 계정으로 실행되므로 이 권한은 사용자가 직접 승인해야 합니다. 기존 서비스에 영향을 주지 않도록 승인 전에는 이 기능을 main에 배포하지 않습니다.

1. 기존 Apps Script 프로젝트 편집창에 아래 함수만 추가합니다. 회원 데이터 변경이나 메일 발송을 하지 않고 권한과 잔여 한도만 확인합니다.

```javascript
function enableRecoveryEmail() {
  console.log(MailApp.getRemainingDailyQuota());
}
```

2. 함수 목록에서 `enableRecoveryEmail`을 선택해 실행하고 소유 Google 계정으로 메일 발송 권한을 승인합니다. manifest의 `oauthScopes`를 명시적으로 관리하고 있다면 기존 항목을 유지하고 `https://www.googleapis.com/auth/script.send_mail`만 추가합니다.
3. 승인 완료 후 이 변경을 main에 반영해 기존 Google 웹 앱과 Pages를 자동 배포합니다. 자동 배포 도구는 기존 manifest를 보존합니다. 소유 계정 권한 승인 전에는 전체 서비스에 새 권한 요구가 생길 수 있으므로 먼저 배포하지 않습니다.
4. Code checks·Pages·Google 실제 업데이트 단계를 확인하고, 본인 이메일 주소로 인증→링크 확인→요청 흐름을 실검증합니다. 실제 회원 비밀번호 재설정은 당사자가 새 비밀번호를 입력할 때만 일어납니다.
