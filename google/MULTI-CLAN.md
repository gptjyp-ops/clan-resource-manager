# 여러 클랜 기능 적용하기

GitHub 사이트에는 클랜 생성·클랜장 로그인·초대 링크·클랜 이름 변경 화면이 추가되었습니다. 저장 서버인 Google Apps Script에도 새 코드를 적용해야 기능이 열립니다.

서버 번호 선택도 지원합니다. 생성·기존 클랜 연결 시 번호를 입력하거나 등록된 서버 목록에서 선택합니다. 클랜장은 관리 화면의 **클랜 서버 저장**으로 나중에 수정할 수 있습니다. 서버 번호는 클랜 현황에도 표시됩니다. 이전 클랜은 **미등록**으로 표시되며 기존 기록은 유지됩니다.

이미 여러 클랜 버전을 배포했어도 서버 번호 기능을 쓰려면 최신 `Code.gs`로 한 번 더 교체하고 기존 웹 앱을 새 버전으로 배포합니다. 클랜 목록의 11번째 `server` 열은 자동으로 추가됩니다. 시트를 직접 바꾸거나 setup을 실행할 필요가 없습니다. 서버 번호 변경은 표시 정보만 바꾸며 다른 클랜의 기록을 가져오거나 합치지 않습니다.

## 이미 운영 중인 구글 스크립트 업데이트

1. 기존 **클랜 재화관리** Apps Script 프로젝트를 엽니다. 새 프로젝트를 만들지 않습니다.
2. `Code.gs`의 기존 내용을 이 저장소 `google/Code.gs`의 전체 내용으로 교체하고 저장합니다. `Bridge.html`은 기존 내용을 유지합니다.
3. **배포 → 배포 관리 → 현재 웹 앱 옆 수정(연필) → 버전: 새 버전 → 배포**를 누릅니다. 기존 웹 앱 주소를 유지합니다.
4. 추가 권한 요청이 나오면 운영 계정에서 확인합니다.
5. GitHub 사이트를 새로고침하고 **새 클랜 만들기 · 클랜장 관리**로 들어갑니다. 연결 업데이트 안내 대신 생성 화면이 나오면 적용된 것입니다.

기존 시트와 사진 폴더를 지우거나 스크립트 속성 `SHEET_ID`, `FOLDER_ID`, `PEPPER`, `CLAN_KEY`를 변경하지 않습니다. 새 코드가 필요한 클랜 목록 시트를 자동으로 만듭니다. 초기 setup을 다시 실행할 필요가 없습니다.

## 기존 우리 클랜 연결

- **기존 클랜 연결**을 선택합니다.
- 클랜 이름, 기존 입장 코드, 새 클랜장 비밀번호(10자 이상)를 입력합니다.
- 기존 닉네임·재화·사진·회원 수정 비밀번호가 그대로 유지됩니다.
- 기존 주소와 입장 코드는 계속 쓸 수 있습니다. 기존 클랜은 한 번만 클랜장 연결을 할 수 있습니다.
- 초대 링크를 변경하면 기존 입장 코드도 무효가 됩니다. 새 링크를 클랜원에게 전달합니다.

## 새 클랜장이 쓰는 방법

1. **새 클랜 만들기**에서 이름과 클랜장 비밀번호를 정합니다.
2. 생성 결과의 **클랜 ID**, **클랜장 관리 주소**, **초대 링크**를 보관합니다.
3. 클랜원에게 초대 링크를 공유합니다. 링크를 받은 사람은 클랜 재화와 사진을 볼 수 있으므로 클랜원에게만 공유합니다.
4. 클랜원은 링크를 열어 **클랜 현황 열기**를 누르고 자기 사진과 재화를 등록합니다.
5. 클랜장은 관리 주소에서 ID와 비밀번호로 로그인하여 이름과 초대 링크를 관리합니다. 재화 현황은 **우리 클랜 재화 현황 열기**로 확인합니다.

클랜장 로그인은 6시간 동안 유효합니다. 새 로그인을 하면 이전 관리 로그인은 무효가 됩니다. 클랜장 비밀번호 분실 시 아래 운영자 복구 절차를 사용합니다.

## 저장과 권한

- 클랜마다 별도의 회원 시트와 사진 폴더를 사용합니다. 같은 닉네임도 클랜별로 독립적으로 저장됩니다.
- 클랜 ID만으로 조회할 수 없습니다. 해당 클랜의 입장 코드가 필요합니다.
- 사진도 해당 클랜 기록과 폴더에 속하는지 함께 확인합니다.
- 클랜장 이름·초대 링크 변경은 해당 클랜의 관리 로그인으로만 가능합니다. 회원 입장 코드로는 변경할 수 없습니다.
- 구글 드라이브·시트의 소유자는 지금 웹 앱을 배포한 운영 계정입니다. 클랜별 분리는 프로그램에서 적용합니다. 각 클랜장이 자기 구글 계정에 저장하는 구조는 아닙니다.
- 클랜장과 닉네임 비밀번호는 검증용 HMAC으로 저장합니다. 초대 코드·검증값이 담긴 시트와 폴더는 외부에 공유하지 않습니다.
- 공유 운영 계정의 무제한 생성 방지를 위해 새 클랜 생성은 하루 총 20개로 제한합니다. Apps Script 실행과 드라이브 용량 한도도 적용됩니다.

## 검증 범위

자동 테스트는 클랜 간 기록·사진 분리, 같은 닉네임, 잘못된 입장 코드, 관리자 권한, 비밀번호 잠금, 로그인 만료, 초대 코드 변경, 기존 클랜 이전을 검사합니다.

구글 코드 적용 뒤 실제 사이트에서 클랜 두 개를 만들고 같은 닉네임 등록, 다른 클랜 사진 차단, 이름 변경, 초대 코드 변경, 기존 기록 유지까지 확인해야 실제 구글 배포 검증이 끝납니다.

## 회원 비밀번호 분실 (2026-10-08)

최신 Code.gs로 교체하고 기존 웹 앱을 새 버전으로 배포하세요. Bridge.html은 변경할 필요가 없으며 setup을 다시 실행하지 않습니다.

클랜장 관리 주소에서 로그인 → **회원 수정 비밀번호 초기화** → **회원 목록 불러오기** → 해당 닉네임 선택 → 새 수정 비밀번호(6자 이상) 두 번 입력 → 해당 회원인지 확인 → **선택한 회원 비밀번호 변경**.

회원에게 새 비밀번호를 개인적으로 전달하세요. 기존 닉네임과 새 비밀번호로 내 재화에 로그인하고 수정할 수 있습니다. 기존 재화·사진·등록일은 그대로이며 이전 비밀번호는 무효입니다. 이 기능은 회원 비밀번호에만 적용되며 클랜장 비밀번호를 복구하지 않습니다.

## 클랜장 ID·비밀번호 분실: 운영자 복구

기존 Apps Script 프로젝트의 Code.gs를 최신 코드로 교체하고 저장합니다. 복구 함수 자체는 편집기에서 실행하므로 웹 앱 재배포 전에 사용할 수 있습니다.

1. 상단 함수 선택에서 `listClansForRecovery` → 실행. 실행 로그의 클랜 이름·서버로 대상 클랜 ID를 찾습니다. 초대 링크의 `clan=` 뒤 값도 같은 ID입니다. ID는 비밀번호가 아닙니다.
2. 왼쪽 톱니바퀴 **프로젝트 설정** → **스크립트 속성** → 다음 두 속성을 추가하고 저장합니다. 기존 SHEET_ID, FOLDER_ID, PEPPER, CLAN_KEY는 바꾸지 않습니다.
   - `CLAN_RECOVERY_ID`: 대상 클랜 ID
   - `CLAN_RECOVERY_PASSWORD`: 직접 정한 새 클랜장 비밀번호(10~100자)
3. 편집기로 돌아가 함수 `recoverClanAdmin` → 실행. 운영 구글 계정으로 실행합니다. 실행 로그에 비밀번호 없이 복구된 클랜 이름과 관리 주소가 표시됩니다.
4. 관리 주소에서 기존 클랜 ID와 새 비밀번호로 로그인합니다. 새 비밀번호를 클랜장에게 개인적으로 전달합니다.

성공하면 복구용 두 속성은 자동 삭제되고 이전 클랜장 비밀번호·로그인은 무효가 됩니다. 재화·사진·회원 비밀번호·초대 링크는 유지됩니다. 새 클랜 생성이나 setup 재실행은 필요 없습니다. 잘못된 ID/비밀번호로 실패했다면 속성을 수정하거나 삭제하세요. 이 함수는 일반 클랜원 요청 및 익명 요청에서 실행되지 않습니다.
