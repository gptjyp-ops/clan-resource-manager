# 구글 저장 연결 — 처음 한 번 설정

클랜원은 GitHub Pages 사이트에서 사진을 올리고 현황을 확인합니다. 사진은 관리자의 구글 드라이브, 기록은 구글 시트에 저장합니다. 회원별 수정 비밀번호와 클랜 공통 입장 코드를 사용합니다. 점수 계산은 포함하지 않습니다.

## 1. Apps Script 만들기

1. 관리할 구글 계정으로 https://script.google.com/ 에 로그인합니다.
2. **새 프로젝트**를 누르고 이름을 `클랜 재화관리`로 정합니다.
3. 기본 `Code.gs` 내용을 이 폴더의 `Code.gs` 전체 내용으로 바꿉니다.
4. 왼쪽 파일 **+ → HTML**에서 이름을 `Bridge`로 만들고 `Bridge.html` 전체 내용을 붙여넣습니다.
5. 저장합니다. Code.gs 맨 아래에 `function setup() { setup_(); }`를 추가한 뒤 상단 함수 선택에서 `setup`을 골라 **실행**합니다. 완료 후 실행용 `setup` 함수는 삭제해도 됩니다.
6. 본인 계정에서 드라이브·시트 사용 권한을 허용합니다. 실행 로그에 나온 **클랜 입장 코드**는 클랜원에게만 전달합니다.

이 단계에서 `클랜 재화관리` 시트와 `클랜 재화관리 사진` 폴더가 자동 생성됩니다. 두 파일의 공유 권한을 공개로 바꾸지 마세요. 코드에는 구글 계정 비밀번호를 넣지 않습니다.

## 2. 웹 앱 배포

1. 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형에서 **웹 앱**을 선택합니다.
3. 실행 계정은 **나**, 액세스 권한은 **모든 사용자(Anyone)**를 선택합니다.
4. 배포하고 `/exec`로 끝나는 **웹 앱 URL**을 복사합니다. 이 URL은 공개 연결 주소이며 계정 비밀번호가 아닙니다.

익명 웹 앱 호출 자체는 허용하지만 서버가 클랜 입장 코드를 확인합니다. 기록 수정에는 해당 닉네임의 비밀번호도 필요합니다. Workspace 조직 계정은 관리자 정책에 따라 모든 사용자 배포가 막힐 수 있습니다.

## 3. GitHub Pages 연결

1. 현재 웹 앱 URL은 `src/lib/google-config.ts`에 연결되어 있습니다. 배포를 바꿨다면 이 파일의 주소를 바꾸거나 GitHub Actions 변수 `VITE_GOOGLE_SCRIPT_URL`로 재정의합니다.
2. **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다.
3. **Actions → Publish GitHub Pages → Run workflow**를 실행합니다.
4. 배포가 성공하면 Pages에 나온 실제 사이트 주소에서 클랜 입장 코드를 입력합니다.

현재 저장소 이름이 `-`여도 작동하며, 이름을 바꾸면 다음 배포에서 경로가 자동 적용됩니다. 입장 코드는 GitHub 변수나 코드에 넣지 않습니다. 사이트를 여는 클랜원이 직접 입력합니다.

## 운영과 확인

- 스킬, 알, 알 합성, 탈것, 탈것 합성, 물약 사진을 각각 저장합니다.
- 숫자 인식은 브라우저에서 진행합니다. 저장 사진은 긴 변 최대 1600px, JPEG 1MB 이하로 압축합니다. 숫자 인식은 업로드 원본을 사용합니다.
- 같은 닉네임에 새 사진을 등록하면 해당 종류의 이전 사진은 휴지통으로 이동합니다. 구글 드라이브 휴지통도 용량을 사용하므로 관리자가 주기적으로 비워야 합니다.
- 저장된 사진은 입장 코드가 있는 클랜원이 사이트에서 볼 수 있습니다. 드라이브 링크를 공개하지 않습니다.
- 입장 코드를 바꾸려면 Apps Script **프로젝트 설정 → 스크립트 속성**의 `CLAN_KEY`를 새 임의 문자열(16자 이상)로 바꿉니다. 클랜원은 사이트에서 다시 입장합니다.
- 닉네임 비밀번호는 서버 전용 비밀키를 사용한 HMAC으로 저장됩니다. 닉네임 비밀번호 자동 복구는 아직 없습니다. 여러 클랜의 클랜장 관리 기능은 아래 별도 안내를 따릅니다. 시트에는 비밀번호 검증용 값이 포함되므로 시트 자체는 공유하지 마세요.
- Apps Script 실행 및 드라이브 용량에는 한도가 있습니다. 사용 한도를 넘기면 요청이 실패할 수 있습니다.
- 구글 배포 후 실제 iPhone/PC에서 첫 등록, 새로고침, 다른 기기 조회, 비밀번호 오류, 사진 보기까지 확인해야 운영 검증이 끝납니다.
- Apps Script 코드를 수정하면 **배포 → 배포 관리 → 수정 → 새 버전**으로 업데이트합니다. 구글 웹 앱을 제거하면 GitHub 사이트의 저장 기능도 멈춥니다.

## 여러 클랜과 클랜장 관리

여러 클랜 기능의 기존 구글 프로젝트 업데이트, 기존 클랜 연결과 운영 방법은 [MULTI-CLAN.md](./MULTI-CLAN.md)를 따릅니다. 클랜장 비밀번호 로그인과 클랜별 데이터 분리가 추가되었으며 비밀번호 자동 복구는 아직 없습니다.

## 기존 재화 보존 수정 (2026-10-04)

`Code.gs`를 새 코드로 교체하고 기존 웹 앱 배포를 새 버전으로 업데이트해야 합니다. 이번 수정은 `Bridge.html` 변경이 없습니다. 재배포 후 사이트를 새로고침하세요. 새 사이트는 이전 서버에서의 덮어쓰기를 방지하기 위해 업데이트 전 저장을 차단합니다.

기존 닉네임과 수정 비밀번호로 저장하면 변경한 필드만 갱신합니다. 빈칸·미인식 값·수정하지 않은 항목·기존 사진은 유지하고, 직접 입력한 `0`은 정상적으로 갱신합니다. 합성 수량을 별도로 올려도 소환 수량과 레벨은 유지합니다. 100레벨로 바뀐 항목만 이전 단계·진행 기준을 비웁니다. 이미 덮어써서 없어진 숫자를 자동 복구하는 기능은 아닙니다.

`Code.gs`와 `Bridge.html`을 모두 교체하고 기존 웹 앱 배포를 **새 버전**으로 업데이트하세요. 클랜에 입장한 사용자의 인식 실패가 `클랜 재화관리` 구글 시트의 `ocr_errors` 탭에 자동 기록됩니다. 공개 연습 페이지는 자동 전송하지 않습니다.

전송 내용: 수신 시각, 클랜 ID, 앱 버전, 화면 종류, 인식 모드, 사진 크기, 오류 코드, 숫자로 제한한 인식 결과. 원본 사진·파일명·닉네임·비밀번호·초대 코드는 보내지 않습니다. 사진 자체가 필요한 경우 사용자가 따로 제공해야 합니다.

클랜별 30초에 한 건, 시간당 최대 120건이며 전체 최신 1,000건을 보관합니다. 전송 실패가 재화 입력이나 저장을 막지 않습니다. 구글 시트 소유자만 전체 로그를 확인할 수 있으며 클랜원 조회에는 포함되지 않습니다. 이메일·카톡·ChatGPT 알림은 연결하지 않습니다.
